# 查询理解基线（2026-10-30）

数据：`query-understanding-seed-v1-20261030`，30 条（24 开发 + 6 保留），标签为 `agent_prepared`，尚未人工批准。

## 结果

| 指标 | 规则 | LLM 规划器 |
|---|---:|---:|
| 意图准确率（精确） | 73.3% | 46.7% |
| 意图准确率（事实族合并） | 83.3% | **93.3%** |
| 路由准确率 | **73.3%** | 56.7% |
| Mention Precision | **96.3%** | 94.4% |
| Mention Recall | 43.3% | **85.0%** |
| Mention F1 | 59.8% | **89.5%** |
| 时间区间精确匹配 | **90.0%** | 85.0% |
| 澄清 Precision / Recall | 0 / 0 | 0 / 0 |

“规则”= `compile_research_plan()` 的确定性回退路径；“LLM”= 现有 `plan_question()`，单次运行，temperature=0。

## 结论

**1. 长尾实体靠规则确实覆盖不了。** 规则 mention recall 只有 43.3%，事件、文献、地点、会议简称和组合简称基本都漏；LLM 把 recall 拉到 85%。这支持“LLM 生成候选 + 实体索引接地”的方向。

**2. LLM 的意图标签和现有 taxonomy 不一致。** LLM 大量输出 `event_overview`，而用例期望 `general`/`timeline`。按“事实族”合并后准确率 93.3%，说明它理解大致正确，但精确枚举不稳定。正式落地前要把 intent 定义收敛，或者让下游只依赖事实族 + route。

**3. 路由反而更差。** LLM 对简单事实问题也走 `deep`，路由准确率 56.7%，低于规则的 73.3%。说明“改写深度由意图决定”不能只靠模型自觉，需要确定性路由策略。

**4. 两边都不会澄清。** 3 条应澄清的关键词式查询（`qu_dev_keyword_dump`、`qu_hold_multi3_mao_liu_zhou`、`qu_hold_keyword_dump_longmarch`），LLM 的 `needs_clarification` 全为 false。这是当前最直接的用户体验缺口。

**5. 时间解析有一个真实 bug。** `只依据《邓小平年谱（1904—1974）》下卷，1973年3月…` 被 LLM 解析成 1904—1974，把书名卷次年份当成了事件时间；规则路径因为先剥离书名，得到 1973。需要独立的“书名年份不得进入时间约束”校验。

**6. 实体接地过严，组合简称会被丢掉。** `刘邓在1947年共同指挥了哪些战役？` 的 LLM 预测 canonicals 为空；`国共两党` 也类似。原因是 `_entity_is_grounded()` 只允许实体文本/规范名出现在问句里，模型把 mention 写成“刘伯承、邓小平”时会被判不接地。需要允许“原始 mention → 多个规范实体”的接地方式。

## 已知限制

- 30 条种子集不足以覆盖所有意图；标签未经人工批准。
- LLM 有非确定性：两次运行精确意图准确率从 50.0% 变到 46.7%，本报告是单次结果。
- 规范名比较做了等价归一（会议全称、书名卷次、运动/时期后缀、多实体分隔），仍可能有边界争议。
- 该基线只测“理解”，不测检索和答案。

## 下一步（P1）

1. 建实体索引 v1：人物、会议、文献优先，带别名、时间范围、文档/页码；
2. mention 检测改为“词典最长匹配 + LLM 候选”合并，支持一个 mention 对多个实体；
3. 修 `_entity_is_grounded()` 的组合简称问题；
4. 加书名年份防泄漏校验；
5. 澄清策略独立实现，不依赖 LLM 自觉；
6. 人工复核这 30 条标签后，再扩到 50 条并分开发/保留。
