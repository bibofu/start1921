# 日期校验校准记录（2026-10-24）

本文件记录生产引用检查中"日期"信号的一次离线校准，用于决定该信号能否进入交付链路，以及进入后应采取什么动作。结论是**只提示、不改写**；本文不是 Golden 成绩，也不构成人工验收。

## 1. 要回答的问题

BC-043 移除了生产链路的日期校验，原因是旧校验会误伤正确回答并触发一次模型修复，修复失败后整篇降级为摘录。旧判定的具体问题是：

- 它只在**420 字引文**（`citation.quote`）里找"X 月 X 日"，而引文是围绕查询词裁出的窗口，日期常常落在窗口之外；
- 它是"任一问题即整篇失败"的二元判定，没有精度分级。

因此需要先测：改成"用 chunk 全文比对 + 精度子集"之后，旧规则的标记里有多少是真错误，新规则又会标记多少。

## 2. 语料与方法

| 项 | 内容 |
| --- | --- |
| 问题集 | 2026-10-05 观测采集中的 13 道题（同一批题面） |
| 运行时间 | 2026-10-24，当前生产链路（无日期校验） |
| 模型 | `deepseek-v4-pro`（配置默认） |
| 有效答案 | 11 道 LLM 答案；2 道为摘录式兜底/拒答，未计入 |
| 日期样本 | 19 个"年+月（+日）" |
| 全文来源 | `data/processed/chunks/*.jsonl`，按 `document_id + pdf_page` 与引文前缀定位 |
| 判定口径 | 旧：`validate_grounded_answer` 的 `_citation_supports_date`；新：`citation_check` 的全文 + 精度子集 |

为什么重新跑题：2026-10-05 的采集是在旧校验仍生效时产生的，凡是触发过修复或降级的答案已经被改写或转成摘录，直接回放会系统性低估问题。2026-10-24 的运行没有日期校验，答案保持模型原样，适合作为校准语料。

## 3. 结果

| 指标 | 数值 |
| --- | ---: |
| 日期总数 | 19 |
| 旧规则标记 | 3（15.8%） |
| 新规则判定"同一年份无对应月份"或"年份不符" | 0 |
| 新规则判定"证据只有月份、答案写到日"（partial） | 2 |
| 新规则判定 supported | 17 |
| 生产实际输出的日期提示 | 0 条 |

逐条核对旧规则标记的 3 处（Agent 复核，非人工批准）：

| 题 | 日期 | 所引证据 | 核对结论 |
| --- | --- | --- | --- |
| `pilot_multievidence_zunyi_leadership` | 1935年2月5日 | 《邓小平年谱（1904—1974）上卷》p124 | 该页 OCR 文本为"1935年2月共中央政治局常委在此召开会议"，只有月份；2月5日另在同页另一 chunk（未被本句引用）。属**引文不足**，日期本身正确 |
| `dev_exact_deng_1954` | 1954年9月28日 | 《邓小平年谱（1904—1974）中卷》p552 | 该页覆盖 9 月 16/19/24 日等记载，28 日不在此页。属**引文不足**，日期本身正确 |
| `pilot_negative_cppcc_1949` | 1949年8月 | 周恩来年谱 p437、毛泽东年谱 p12 | 该句是"第2组证据覆盖1949年8月底至9月30日……"的**资料范围说明**，不是史实断言 |

即：旧规则的 3 次标记没有一次是"错误日期"，全部属于引文覆盖不足或元信息句。旧方案若继续生效，这 3 道题会被判 `citation_date_mismatch`，按 BC-043 的旧逻辑可能整篇降级为摘录。

新规则的 2 处 `partial` 对应上表前两行：月份相符、日不在所引 chunk 内。这类情况数量不小（若按"答案精度高于证据"统计为 7/19），因此**降精度会改动大量真实日期**，是不可接受的取舍。

## 4. 与旧方案的取舍

| 方案 | 对 19 个日期的影响 | 结论 |
| --- | --- | --- |
| 旧规则：失败即降级 | 3 道题有降级风险，且 3 处均为误伤 | 不采用 |
| 降精度（日→月→年） | 至少 7 处被改写，其中包含真实日期 | 不采用 |
| 删除冲突日期 | 0 次触发，但一旦触发会删掉可能是真实的日期 | 不采用 |
| **全文比对 + 只提示** | 0 次触发；触发时只增加一条"请核对"说明 | **采用** |

## 5. 生产实现

- `HISTORY_AGENT_CITATION_CHECK=s1_dates`（默认）：S1 移除假编号/错页码，并对日期给出核对提示；`s1` 只做前者；`off` 全部关闭。
- 日期提示只覆盖"年份不符"或"同一年份没有对应月份"两种情况；"答案精度高于证据"不提示。
- 日期永不改写：CJK 日期（如"一九六一年三月十三日"）通常出现在原文引用中，改动会篡改史料文本，因此只解析阿拉伯数字日期。
- 提示文案只说"在所引证据的同一时期中没有对应记载，请回到原文核对"，不断言日期错误。

## 6. 局限

- 样本为 11 道答案、19 个日期，只能支持"不误伤"的判断，不足以估计稀有错误的召回率；异常召回由注入测试覆盖（改错年份/月份必须被识别）。
- 全部判定为 Agent 复核，未经过人工批准，不能当作正式评测成绩。
- 日期提示按"同一行引用标记"归属，段落跨行引用时可能漏判；漏判方向是"不提示"，不会误删。
- 只覆盖阿拉伯数字日期；OCR 文本中的中文日期仅在比对证据时归一化，答案侧忽略。

## 7. 后续

真正的改进方向不是删日期，而是提高**引文充分性**：上表两处 `partial` 说明模型引用了相邻页/相邻 chunk，而事实在邻近片段中。候选方案依次为：

1. 召回后扩展 `previous_chunk_id` / `next_chunk_id`，让证据包覆盖完整条目；
2. 引用时把同页多个 chunk 合并为该事件的最小完整段落；
3. 再评估"日期覆盖"是否随引文充分性提升而自然下降。

在这些改造完成前，日期信号保持"只提示"。
