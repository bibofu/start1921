# 关键词索引 jieba 基线（2026-10-31）

## 当前实现

- 索引版本：`postgresql-bm25-jieba-v1`
- tokenizer：jieba `0.42.1`，`lcut_for_search`
- 索引：22,338 chunks，4,881,925 倒排记录，7,873,208 词位，约 134 MB
- 关键词分支平均耗时：419 ms；完整混合检索平均 303 ms
- 查询端保留年份扩展、停用词、虚词边缘过滤，以及人物/年份/文献/章节过滤

## 同管线离线基线

- 数据集：`golden-v2.7-selected-20-20261030` 的 18 道可答题；题目、证据组、人工标签和固定池未改动。
- 检索：`search_hybrid_index`，原问题直接检索，`candidate_k=30`、`top_k=20`、无 LLM 计划。
- 指标：`evaluate_stage` + 人工批准标签 + 固定池；unknown 不按 0 分，不可评不计入宏平均。

| 指标 | jieba | 可评题数 |
| --- | ---: | ---: |
| Recall@10 | 0.551 | 18 |
| Recall@20 | 0.635 | 18 |
| Precision@5 | 0.673 | 11（配对） |
| MRR@10 | 0.971 | 17 |
| nDCG@5 | 0.779 | 11（配对） |

## 与切换前正式基线

切换前的正式成绩为 Recall@10 62.6%、Recall@20 67.0%、P@5 65.0%、MRR@10 0.971、
nDCG@5 0.724。两组成绩的固定池均按旧候选采集，jieba 会召回池外页面；这些页面在
标注体系里是 unknown，不是不相关。因此 P@5/nDCG 的可评题数下降，只有配对子集可比，
不能把两组数字直接当作提升或回归。

## 解释边界

- 这是同一向量/RRF 管线的离线对照，不是重新完成的正式 Golden 成绩。
- 18 道题样本量不足以确认几个百分点的差异；一个证据组就能造成明显的题内波动。
- 当前词典未加入人物别名、文献标题、机构名和历史专名；这是朴素 jieba 的下限。

## 后续

1. 通过 `HISTORY_AGENT_JIEBA_DICT` 或 `config/jieba_userdict.txt` 补充领域词典，重跑本基线。
2. 只调 RRF 权重或 `candidate_k`，保持索引不变。
3. 扩池补标并增加题量，让 P@5/nDCG 有可比分母，再判断是否更新正式口径。
