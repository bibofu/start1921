# 2026-11-01 Jieba 开发集词表实验（未采纳）

## 假设

在 `config/jieba_userdict.txt` 中加入 20 个**仅从 22 道开发题/证据推导**的历史领域词，重建关键词索引，看是否能提升 Golden v1.2 的检索指标。

## 结论

**未采纳。**

- 召回没有提升，Recall@5/@20 反而下降 0.0089；
- P@5 / nDCG@5 有很小提升，但主要来自单题，且与 Recall 下降同时出现，不能判定为稳定收益；
- 保留集完全不变，说明收益没有泛化证据；
- 词表加入后索引 artifact 变化，但没有带来可归因的召回改善。

已回退：

- `config/jieba_userdict.txt` 恢复为 281 条；
- `scripts/build_jieba_userdict.py` 恢复；
- 重建 keyword index：run `fb36f49a02024ae782e4a1cc154a5d3f`，artifact SHA-256 与基线完全一致：
  `037df8ef5a1564ce4f0dd65f7e1ca981ed919e6d818e639eb5776f50a2d23642`。

## 下一步

这次实验说明：**对这些 golden query，单纯加 jieba 词典不是主要杠杆。** 更值得试的是：

1. query alias / query expansion：
   - `党的头一次全国大会 → 中共一大`
   - `恢复联合国合法席位 → 2758号决议 / 恢复中华人民共和国在联合国的一切合法权利`
   - `两弹一星 → 原子弹 / 氢弹 / 人造卫星`
   - `长征期间召开的会议 → 通道会议 / 黎平会议 / 遵义会议 / ...`
2. 召回缺口：`holdout_exact_date`、`holdout_semantic_observation` 没有章节命中，先查切分/索引覆盖，不是词典问题。
3. 如果要继续词典方向，应先从 **dev query 中实际被切碎且出现在 query 里的词** 入手，并单独做消融；不要一次加 20 个长事件名。
